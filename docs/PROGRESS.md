# Состояние проекта

Дата: 2026-10-09. Версия пакета: 0.1.0. Код в GitHub: https://github.com/Lightwell-bg/bginfosu_bot (ветка main).

## Что сделано (модули)

| Модуль | Состояние |
|---|---|
| `config.py`, `config.ini`, `.env.example` | Секреты из `.env`, константы из `config.ini` (модели, лимиты, срок хранения, параметры админки) |
| `db/` | SQLite (WAL), автоматические миграции при старте, таблицы выпусков, черновика, анкет, результатов, заявок, учёта AI, событий |
| `kb/` | Модель базы знаний (основания, показатели, факты, вопросы, источники), проверка (`validate`), выпуски: черновик, публикация с датой, откат, отмена запланированного, срочная пометка «требует проверки», сравнение |
| `engine/` | Трёхзначная оценка условий (да / нет / неизвестно), статусы оснований, планировщик вопросов, диалог (конечный автомат без привязки к Telegram), формирование результата, семья, пересчёт при смене выпуска |
| `ai/` | Клиент OpenRouter (JEV System One и chat/completions со строгой схемой), разбор текста, извлечение сумм, объяснение результата с программной проверкой и откатом на шаблон, суточный бюджет и лимиты на пользователя ([PROMPTS.md](../PROMPTS.md)) |
| `bot/` | Адаптер aiogram 3: long polling, защита от дублей `update_id`, кнопки с номером ревизии, блокировка по пользователю, заявка на консультацию с защитой от повтора, автоочистка, отказ стартовать при webhook и при демо-выпуске в production |
| `admin/` | FastAPI-админка: вход (argon2, ограничение попыток), CSRF, редакторы оснований / показателей / фактов / вопросов / источников, проверка и публикация, история и откат, «требует проверки», тестовая анкета, статистика |
| `seed/` | Начальное наполнение: 13 карточек-черновиков и каталог по [KB_RESEARCH.md](research/KB_RESEARCH.md), сборка отдельной демо-базы |
| `ops/` | Бэкап и восстановление SQLite с проверкой  |
| `scripts/` | `smoke_live.py` и `jev_eval.py` (живые вызовы OpenRouter) |
| `Dockerfile`, `docker-compose.yml` | Сервисы `bot`, `admin`, профиль `ops` для бэкапа |
| Документация | README (EN основной, RU в README_RU.md), QUICK_START, DEPLOY, SWITCHOVER, KB_MANUAL_UPDATE, KB_GAPS, PRIVACY, TEST_SCENARIOS, PROMPTS, JEV_EVAL |

## Какие проверки выполнены

- **Автотесты** (`pytest`): 202 прошло, xfail и падений нет. Покрыты конфигурация, движок, диалог, рендер, выпуски, админка (FastAPI TestClient), бэкап, учёт AI, клиент OpenRouter, наполнение, адаптер Telegram, сквозные сценарии.
- **Линтер** (`ruff check .`): ошибок нет.
- **Живой OpenRouter проверен:** `scripts/smoke_live.py` (полный путь анкеты с реальными JEV и LLM) и `scripts/jev_eval.py` (20 размеченных примеров: 31 ожидаемое направление, пропущено 0, ложных срабатываний 0; один случай помечен «неясно» и будет спрошен явно; стоимость прогона около $0,005). Результаты: [JEV_EVAL.md](JEV_EVAL.md). Ноль пропусков на этой выборке не означает гарантированной точности.
- Формат вызова JEV (`POST /systemone`, модель `~typesafe/jev-latest`, типы `noul` / `choice` / `score`, стоимость в `usage.cost`) проверен живым вызовом 2026-10-09.

## Что не проверено

- **Docker-сборка и запуск НЕ выполнялись:** Docker на машине разработки отсутствует. `Dockerfile` и `docker-compose.yml` не собирались и не запускались; первая сборка на сервере станет первой проверкой. Известные риски, которые надо проверить при первом запуске: адрес прослушивания админки внутри контейнера (теперь `network_mode: host`, адрес и порт в `config.ini`; проверить доступность порта 8091 снаружи), права на том `/data`, работа `docker compose cp` и команд бэкапа из DEPLOY.
- **Живой Telegram не проверялся:** нет тестового токена. Не проверены реальные клавиатуры, редактирование сообщений, ограничения длины, поведение при webhook, настоящий long polling.
- **Тесты aiogram идут на фейковой сессии (моки):** `tests/fake_tg.py` подменяет Telegram, это не интеграционная проверка.
- Сценарии из [TEST_SCENARIOS.md](TEST_SCENARIOS.md) выведены из логики карточек и не пройдены вручную в Telegram.
- Админка проверена только тестовым клиентом FastAPI, в браузере не открывалась (вёрстка, JavaScript-конструктор условий не проверялись глазами).
- Резервное копирование и восстановление проверены тестами на файловой базе; на сервере и по cron не запускались.
- Содержимое базы знаний юридически не проверено: все карточки — черновики, см. [KB_GAPS.md](KB_GAPS.md).
- Член семьи, когда заявитель уже живёт в Болгарии: его статус в Болгарии не спрашивается, поэтому его собственные основания остаются «нужно уточнить» — осознанное ограничение MVP.

## Что осталось владельцу перед production

1. Завести тестового бота у BotFather и пройти [TEST_SCENARIOS.md](TEST_SCENARIOS.md) в живом Telegram на демо-базе.
2. Пополнить баланс OpenRouter, при желании повторить `scripts/smoke_live.py` и `scripts/jev_eval.py`; проверить настройки приватности аккаунта OpenRouter ([PRIVACY.md](PRIVACY.md)).
3. Проверить сборку и запуск Docker на сервере ([DEPLOY.md](DEPLOY.md)).
4. Загрузить рабочее наполнение (`seed-draft`), пройти все карточки по [KB_GAPS.md](KB_GAPS.md): сверить нормы с Държавен вестник, подтвердить требования (источник, дата, автор), проверить показатели (минимальная пенсия, сумма для Digital nomad, порог по недвижимости), заполнить дату и автора проверки основания, опубликовать выпуск ([KB_MANUAL_UPDATE.md](KB_MANUAL_UPDATE.md)). Демо-выпуск в рабочую базу не загружать.
5. Определить контакт для консультации (`[bot] consult_contact`) и `CONSULT_CHAT_ID`.
6. Решить вопросы приватности: текст политики, срок хранения (`retention_days`) ([PRIVACY.md](PRIVACY.md)).
7. Настроить ежедневный бэкап и хранение копий вне сервера, проверить восстановление ([DEPLOY.md](DEPLOY.md), раздел 10).
8. Дать разрешение на переключение и провести его по [SWITCHOVER.md](SWITCHOVER.md): боевой бот не останавливается и его токен не используется до этого.
9. Поставить тег выпуска (например, `git tag v0.1.0 && git push origin v0.1.0`).

## Доступ к админке (2026-10-09)

По решению владельца админка по умолчанию открыта напрямую по `http://IP:8091` (`network_mode: host`, `[admin] host/port` в `config.ini`, без переменных окружения). Страница «Доступ к админке» меняет host/port и перезапускает админку. Прежние переопределения host/порта через `.env` убраны.
