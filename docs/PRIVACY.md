# Персональные данные: что хранится и куда отправляется

Описание того, как работает код. Это не юридическое заключение и не политика конфиденциальности для публикации: текст политики и правовые основания обработки определяет владелец.

## Что бот не собирает

- **Паспортные данные и документы не запрашиваются и не сохраняются.** Анкета спрашивает только категории («гражданство: другой страны», «получаю пенсию»), суммы и да/нет. Вложения (фото, документы) бот не скачивает и не сохраняет: на них он отвечает просьбой отвечать кнопками или текстом.
- Имя, телефон, адрес, дата рождения не запрашиваются. В уведомлении об AI (ниже) человека просят не присылать номера паспортов, сканы и контакты.
- Исходный текст сообщений **не сохраняется** в базе: в сессии лежат только разобранные структурированные ответы.
- Username Telegram **не сохраняется** в базе. Он используется только в одном месте: в тексте заявки на консультацию, если человек сам её отправил.

## Что хранится (SQLite, файл `app.db`)

| Таблица | Что внутри | Когда удаляется |
|---|---|---|
| `users` | числовой id Telegram, время первого и последнего обращения, время показа уведомления об AI | `/delete`; автоочистка |
| `sessions` | анкета: структурированные ответы (гражданство, виды дохода, суммы вроде размера пенсии, состав семьи, наличие жилья, цель), состояние диалога, номер выпуска базы | `/delete`; автоочистка |
| `results` | показанный текст результата и статусы по основаниям | вместе с сессией |
| `consult_requests` | текст заявки на консультацию (контакт в Telegram: username или id, анкета, предварительный подбор) | `/delete`; вместе с сессией |
| `ai_calls` | учёт вызовов AI: время, id пользователя (до удаления), тип, модель, токены, стоимость, статус (резерв/закрыт), код ошибки (только фиксированные коды). **Текстов нет.** | `/delete` (id обнуляется); автоочистка обнуляет id в записях старше `retention_days`, суммы и токены остаются для статистики расходов |
| `rate_counters` | суточные счётчики лимитов AI: хэш пользователя (SHA-256 от случайной соли и id, сам id не хранится), день, тип, число вызовов. Нужна, чтобы `/delete` не сбрасывал дневной лимит | **не удаляется при `/delete`**; автоочистка удаляет строки старше 2 дней |
| `app_meta` | служебная соль для хэша пользователя | не очищается |
| `events` | счётчики событий для статистики: тип, номер сессии, короткая деталь (например, число распознанных сведений). Текстов и персональных данных нет | через срок хранения (как анкеты): в событиях есть номер сессии |
| `stats_results` | обезличенная статистика результатов: **только дата** (без времени, в часовом поясе бота), номер выпуска, вид результата, основание «проверить первым», статусы оснований, категории ситуации (кто переезжает, гражданство, виды дохода, связи, цель, есть ли семья), число членов семьи. **Нет id пользователя, номера сессии, сумм и текстов** | **не удаляется при `/delete` и по сроку хранения**. Telegram id и связи с анкетой в таблице нет, хранится только дата. Пока анкеты и события не удалены по сроку хранения, в малых выборках (например, один результат за день) связь с конкретной анкетой теоретически возможна по совпадению даты и категорий; после срока хранения — нет |
| `processed_updates` | номера обновлений Telegram для защиты от дублей | через 7 дней |
| `admin_login_attempts` | IP и время попыток входа в админку | через 30 дней |
| `audit_log` | действия владельца в админке | не очищается |

Логи сервисов не содержат текстов пользователей и токенов. Бэкапы (`/data/backups`) содержат копию всей базы целиком.

## Что отправляется в OpenRouter

Свободный текст и структурированные ответы отправляются в OpenRouter (<https://openrouter.ai>) и далее провайдерам выбранных моделей. Кнопочные ответы без вызова AI наружу не отправляются.

| Вызов | Что уходит | Что не уходит |
|---|---|---|
| JEV (разбор текста) | текст сообщения человека (не больше 4000 символов, на практике не больше 1500); список атомарных вопросов из базы знаний | id, username, имя, id чата |
| Извлечение сумм | тот же текст (не больше 2000 символов) и список денежных полей; только если в тексте есть цифра | то же |
| Объяснение результата | компактный профиль: подписи и значения подтверждённых ответов, названия оснований, статусы и подписи выполненных / невыясненных условий | исходный текст человека, id, username |

Подробно — [../PROMPTS.md](../PROMPTS.md). Без `OPENROUTER_API_KEY` ничего не отправляется. Условия хранения запросов у OpenRouter и провайдеров моделей определяют их политики и настройки вашего аккаунта (раздел Privacy в настройках OpenRouter): владельцу нужно ознакомиться с ними и выставить подходящие настройки до открытия бота пользователям.

Заявка на консультацию уходит в Telegram-чат `CONSULT_CHAT_ID`, только если человек сам нажал «Отправить» после предпросмотра. Это сообщение остаётся в чате получателя и **не удаляется** командой `/delete`.

## Уведомление пользователю

Уведомление показывается в приветствии (`/start`) и при выборе «Описать ситуацию самому»; если человек прислал текст, не увидев его, оно выводится перед разбором. Текст уведомления:

> Если пишете своими словами, текст кратко анализируется AI-сервисом (через OpenRouter), чтобы понять вашу ситуацию. Не присылайте номера паспортов, сканы и контакты. Удалить анкету: /delete.

Факт показа сохраняется в `users.ai_notice_at`. Результат сопровождается пометкой, что это предварительный подбор, а не гарантия решения. Если нужна полная политика конфиденциальности (оператор, цели, сроки, права пользователя), её готовит владелец; бот ссылки на неё сейчас не показывает.

## Удаление: `/delete`

Команда `/delete` спрашивает подтверждение («Удалить» / «Отмена»). После подтверждения:

- удаляется запись пользователя; анкеты (`sessions`) и результаты (`results`) удаляются каскадом;
- удаляются заявки на консультацию (`consult_requests`);
- в `ai_calls` id пользователя заменяется на пустое значение (учёт расходов остаётся без привязки к человеку);
- `rate_counters` (необратимый хэш, не id) сохраняется до двух суток, чтобы удаление данных не сбрасывало дневной лимит запросов к AI.

## Срок хранения и автоочистка

- `retention_days` в `config.ini`, секция `[privacy]` (по умолчанию **90 дней**).
- Бот раз в 6 часов удаляет анкеты, не обновлявшиеся дольше этого срока, затем пользователей без анкет и неактивных дольше срока, а в записях `ai_calls` старше срока обнуляет id пользователя (суммы и токены остаются); результаты и заявки уходят каскадом вместе с анкетой. Строки `rate_counters` старше 2 дней удаляются.
- Изменение срока вступает в силу после перезапуска бота (в Docker — после `docker compose restart bot`, см. [DEPLOY.md](DEPLOY.md)).

## Бэкапы и ограничения удаления из них

- Бэкап базы создаётся командой `docker compose --profile ops run --rm backup` (по расписанию — ежедневно) и хранится `backup_retention_days` дней (по умолчанию 14), затем удаляется при следующем бэкапе. Страховочные копии прежней базы перед восстановлением (`app-prerestore-*.db`) лежат в том же каталоге и ротируются по тому же сроку.
- **Удаление анкеты (`/delete` или автоочистка) не затрагивает уже сделанные бэкапы.** Данные остаются в них до ротации, то есть до `backup_retention_days` дней после удаления. Копии бэкапов, скопированные с сервера, автоматически не ротируются: их надо удалять вручную в те же сроки.
- При восстановлении из бэкапа вернутся и данные, ранее удалённые пользователями. Если пользователь запрашивал удаление, после восстановления его надо удалить повторно (вручную в базе: удаление записи в `users` с каскадом).
- Доступ к серверу, томам Docker, бэкапам и `.env` должен быть только у владельца.

## Известные ограничения

- `audit_log` автоматически не очищается (персональных данных в нём нет, но размер растёт). `events` чистятся по сроку хранения, т.к. содержат номер сессии.
- Сообщение с заявкой в чате `CONSULT_CHAT_ID` удаляется только вручную в самом Telegram.
