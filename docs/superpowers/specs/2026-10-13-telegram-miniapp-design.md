# Telegram Mini App «Анкета в виде формы» — дизайн

Дата: 2026-10-13. Статус: утверждено владельцем (ответы на вопросы в чате).

## Что решил владелец

- Мини-апп = та же анкета и тот же расчёт, что в боте, но в виде экранов формы. Бот остаётся как есть.
- В форме есть поле «Расскажите своими словами»: JEV предзаполняет ответы, человек проверяет.
  Объяснение результата — как в боте (тот же `Explainer`, те же лимиты и бюджет).
- Результат показывается в мини-аппе И копией приходит в личный чат с ботом; учитывается в статистике админки.
- HTTPS-домен: `form.bginfo.eu` → сервер 37.27.13.102, сертификат Let's Encrypt через Caddy.

## Выбранный подход: сервер ведёт анкету, мини-апп рисует экраны

Мини-апп — тонкий клиент. Сервер прогоняет тот же `engine.dialog.Dialog` (планировщик, условия, участники
семьи, JEV), что и бот. Логика вопросов в одном месте; бот и форма не расходятся; правки базы знаний в
админке сразу действуют и там, и там. Альтернативы (вся форма на клиенте с условиями в JS; блоки вопросов)
отклонены: первая дублирует движок, вторую можно добавить поверх позже.

**Сессия общая с ботом** (`repo.active_session` по `tg_user_id`): начатое в чате продолжается в форме и
наоборот. Гонки между процессами `bot` и `webapp` закрывает существующая проверка ревизии в
`repo.commit_step` (конфликт → клиент получает актуальный экран).

## Части

### 1. Структурированный экран в `Out` (engine/dialog.py)

`Out.view: dict | None` — машиночитаемое описание текущего экрана, заполняется рядом с `out.say(...)`:

- `question`: `qid, pid, who` (подпись участника или null), `text_html`, `help_html`, `type`
  (bool|enum|multi|money|int|date), `options: [{value,label}]`, `selected: [..]` (multi, с учётом
  распознанного), `allow_unknown`, `can_back`, `can_fix`, `recognized: bool` (предзаполнено из текста),
  `answered: int` (сколько ответов уже есть — для прогресса).
- `review`: `lines: [{index, who, label, value}]` — `index` годится для действия `edit` (тот же
  `s.ui["edit_list"]`, что строит `_edit_menu`).
- `result`: `view` (= `view_to_dict(rv)`), `html`.
- Прочие шаги (подтверждение распознанного, противоречие, приветствие, AI-уведомление, консультация,
  удаление) — `view=None`; клиент рисует `replies[].html` + кнопки универсально.

Новое действие кнопки `multi` (arg = значения через запятую): проверить, что все значения из
`fd.options`, `none` только в одиночку, непустой список → `_commit` как у `done`. Нужно форме, где
выбор копится на клиенте. Ответы money/int/date форма шлёт как `Event("text")` (их разбирает
`parse_simple`); дата из `<input type="month">` переводится в `ММ.ГГГГ` на клиенте.

`Dialog(..., webapp_url: str | None = None)`: если задан, в приветствии бота появляется кнопка
«📝 Заполнить в форме» (action `webapp`, в `bot/render.keyboard` — `InlineKeyboardButton(web_app=...)`).
В самом мини-аппе `webapp_url=None` — кнопки нет.

### 2. Сервис `webapp` (src/bginfo/webapp/)

FastAPI + uvicorn, отдельный процесс `python -m bginfo.webapp`, слушает `[webapp] host:port`
(по умолчанию `127.0.0.1:8092`, наружу только через Caddy).

- `auth.py` — проверка `initData` Telegram: заголовок `Authorization: tma <initData>`; HMAC-SHA256,
  ключ = HMAC_SHA256(key="WebAppData", msg=bot_token); сравнение `hmac.compare_digest`; `auth_date` не
  старше `[webapp] init_data_ttl_hours` (24); из `user` берутся `id, username, first_name, last_name`.
  Иначе 401. Токен бота — существующий `TELEGRAM_BOT_TOKEN`, новых секретов нет.
- `service.py` — один шаг: тот же порядок, что `BotApp._run_locked`: загрузка → `Dialog.handle` →
  ОДНА транзакция `repo.commit_step(update_id=None, ...)` → только потом побочные эффекты.
  Одно sqlite-соединение + однопоточный executor, `asyncio.Lock` на пользователя, отдельное соединение
  для `AiLedger` (как в `build_app`). Обработка `out.restart` — как в боте.
- API (JSON, тело ≤ 8 КБ):
  - `POST /api/open` — `Event("start")`: приветствие или «Продолжить / Начать заново».
  - `POST /api/step {sid, rev, kind: button|text, action, arg, text}` — `sid/rev` обязательны
    (кроме первого шага без сессии); не совпали с активной сессией → 409 + актуальный экран
    (`resume_view`), ничего не применено.
  - Ответ: `{sid, rev, view, replies:[{html, buttons:[[{text, action, arg}]]}], alert}`.
  - `GET /` и `/static/*` — клиент; `GET /healthz`.
- В production на демо-выпуске — отказ (как `demo_release_in_production` в боте).
- Копия результата в чат: после успешного коммита, если `out.result_record` — отправить `message_html`
  (через `split_html`) в личный чат ботом (aiogram `Bot`, без polling), с пометкой «Результат из формы».
  Таймаут 15 с; ошибка доставки только логируется и не ломает ответ (результат уже на экране);
  автоповтора нет (timeout = «возможно доставлено»). Отключается `[webapp] send_result_to_chat = false`.
- Консультация: логику доставки из `BotApp._consult` вынести в общий модуль (`bginfo/bot/delivery.py`),
  которым пользуются и бот, и webapp (та же pending-запись в транзакции, тот же уникальный индекс,
  статусы sent/failed/unknown). В форме итог показывается как `alert`.
- Статистика: события шага помечаются каналом (`session_started` с detail `webapp`), в `result_record`
  добавляется `"channel": "webapp"`; в отчёте «Запуски» в админке виден канал (бот / форма). Если для
  этого нужна колонка — миграция `004_channel.sql` (по умолчанию `bot`).

### 3. Клиент (src/bginfo/webapp/static/)

Чистые HTML/CSS/JS без сборки. `https://telegram.org/js/telegram-web-app.js`. Цвета из
`Telegram.WebApp.themeParams` (светлая/тёмная тема). Экраны:

- вопрос: bool/enum — список-радио, multi — чекбоксы, money/int — числовое поле, date — месяц/год;
  «Не знаю», «Пояснение» (раскрывается), `BackButton` Telegram = действие `back`, `MainButton` =
  «Далее»/«Готово»; бейдж «предзаполнено из вашего текста» при `recognized`; прогресс «Ответов: N».
- поле «Расскажите своими словами» (на приветствии и в любой момент через кнопку) → `kind=text`;
  счётчик символов до 1500; AI-уведомление показывает сервер (как в боте).
- обзор ответов: список с карандашом на каждой строке (`edit`), кнопка «Показать результат» (`review_ok`).
- результат: карточки оснований со статусом, что сделать, ссылки (`view`), кнопки «Почему», «Другие
  варианты», «Изменить ответы», «Консультация», «Начать заново».
- универсальный экран: `replies[].html` + кнопки.

HTML от сервера вставляется только через санитайзер по белому списку: `b, i, u, s, code, pre, br,
a[href^=https:|http:]` (остальное — текстом), `\n` → `<br>`; ссылки открываются через
`Telegram.WebApp.openLink`.

### 4. Развёртывание

- `docker-compose.yml`: сервис `webapp` (`network_mode: host`, healthcheck `/healthz`) и сервис `caddy`
  (`caddy:2`, `network_mode: host`, `Caddyfile` из репозитория: `form.bginfo.eu { reverse_proxy
  127.0.0.1:8092 }`, volume для сертификатов). Порты 80/443 на сервере должны быть свободны —
  в инструкции перед запуском проверка `ss -ltnp`; если их держит другой веб-сервер, вместо caddy
  добавляется его виртуальный хост на `127.0.0.1:8092`.
- DNS: A-запись `form.bginfo.eu → 37.27.13.102` (сейчас её нет).
- Бот при старте, если задан `[webapp] public_url`, ставит кнопку меню `MenuButtonWebApp("Анкета", url)`.
- BotFather не обязателен (кнопка меню и inline-кнопка работают по URL).
- `config.ini [webapp]`: `host`, `port`, `public_url`, `init_data_ttl_hours`, `send_result_to_chat`.
  Новых переменных `.env` нет.

## Крайние случаи

- Устаревший экран (ответили в чате, потом в форме и наоборот) → 409 + актуальный экран.
- Двойное нажатие «Далее» → вторая попытка отклоняется ревизией.
- Пользователь удалил данные `/delete` в чате → в форме следующий шаг начнёт новую анкету.
- AI недоступен / лимит → как в боте: «продолжим кнопками».
- `initData` подделан или просрочен → 401, клиент просит открыть форму заново из бота.
- Пользователь не запускал бота / заблокировал его → копия в чат не дойдёт, это только лог.
- Длинные тексты > 1500 → сообщение от `Dialog`.
- Логи без текстов пользователя и без initData/токенов (`safe_exc`).

## Тесты

- `auth`: верный/неверный hash, просроченный `auth_date`, нет `user`, мусор в заголовке.
- `Dialog.view`: для каждого типа вопроса, review, result; действие `multi` (валидные/чужие значения, `none`).
- API (FastAPI TestClient, фейковые interpreter/explainer/bot): open → вопросы → review → result;
  409 на устаревшей ревизии; копия в чат вызвана один раз после коммита; ошибка отправки не ломает ответ.
- Существующие тесты бота проходят (рефакторинг delivery не меняет поведения).
